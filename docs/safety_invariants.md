# Safety Invariants

`still` is designed around strict safety invariants. These are not just guidelines but hard constraints enforced by the system structure.

## 1. Purge Separation (The "Two-Key" Rule)

**Invariant**: Permanent deletion (Purge) is structurally impossible during the standard `apply` workflow.

* `still apply` executes the Plan.
* The Plan schema supports `Quarantine` and `Trash`, but explicitly rejects `Purge`.
* Purging is a valid action **only** within the `still vault` context.
* Purging requires a specialized "Ritual Phrase" (`PURGE STILL`) that cannot be bypassed by flags.

## 2. No Implicit IO via TUI

**Invariant**: The TUI is a Plan Editor, not a File Manager.

* Actions in the TUI (`Space`, `T`, `Q`) **only** modify the in-memory Plan state.
* No filesystem operations occur until the user exits the TUI and explicitly runs `still apply`.

## 3. Scope Safety (Safe-by-default)

still defines scan scopes to prevent “trust breakage” where the user performs a normal workflow
(`scan -> tui -> apply`) and unexpectedly hits validation errors or unsafe candidates.

### Scope naming policy

* Safe scopes must be named to communicate safety: `*-safe`
* Dangerous scopes must be named to communicate danger: `*-unsafe`
* Ambiguous names (e.g., `full`) are avoided in favor of explicit safety language.

### Scopes

* `library-safe` (default): safe subset of `~/Library` suitable for weekly use
* `library` (alias): alias of `library-safe`
* `library-unsafe`: full `~/Library` scan (advanced / caution)

### Apply compatibility rule

**Invariant**: The default workflow must work.

* A plan generated by `library-safe` must be compatible with `still apply` by default.
* `library-unsafe` may generate entries outside default allowed scopes.
  In such cases, apply may reject actions unless explicitly overridden.

### Scope enforcement rule (Validator)

**Invariant**: Scope containment is enforced only for entries that would be executed.

* Scope checks apply to entries where `action != Keep` (i.e., actions that cause filesystem changes).
* Entries with `action == Keep` are not executed and do not require scope containment.
* This prevents “plan contains harmless Keep entries outside scope” from blocking apply.

### User-facing safety guidance

* Always review `reason` in the TUI before changing actions.
* Prefer `--dry-run` when using `library-unsafe`.
* Permanent deletion remains strictly separated:

  * `still apply` cannot purge
  * purge is Vault-only and ritualized (`PURGE STILL`)

## 4. Symlink & Special File Rejection

**Invariant**: `still` never operates on symlinks or device files.

* **Scan Phase**: Symlinks may be recorded but marked as skipped or unsafe (implementation dependent).
* **Apply Phase (JIT)**: Before any IO sequence, the target is re-verified. If it is a symlink or special file, the operation is **rejected immediately** with a security error. This prevents TOCTOU (Time-of-Check Time-of-Use) attacks where a file is replaced by a symlink after scanning.
